## Observed patterns
- Every skill lives in `skills/<name>/SKILL.md` with `name` + `description`, plus an optional `argument-hint`.
  - `tasks` and `publish` set `user-invocable: false`: hidden from the `/` menu, callable only by other skills.
- Shared content is written once and reached at runtime, never copied (see `decisions/004`).
  - `skills/feature/workflow.md` holds the whole implementation workflow; `feature` and `fix` read it first and define only their specifics.
  - `skills/review/SKILL.md` holds the finding contract (format, severity scale, read-only rule) and injects it into every review agent's prompt.
  - `vibe:publish` holds push-and-release, used by `/vibe:auto --push` and `/vibe:next-task`.
- `feature`, `fix`, `review`, `docs`, `release`, `init`, and `workspace-init` create their task list through `vibe:tasks`, which owns the scratchpad fallback and the `●`/`✓` status-line convention; `auto` prints the same glyphs per item.
- Every agent lives in `agents/<name>.md` with `name` + `description`; review agents also declare `tools` (read-only, plus `Bash` for `review-tests`, `review-dependencies`, `review-web-security`).
  - `review-*`: one dimension each, body = scope sentence + checklist + `## Categories`.
  - `expert-*`: one domain each, body = scope sentence (with out-of-scope routing) + checklist; the consultation formats are stated in `workflow.md`.
  - Experts cover domains without a `review-*` counterpart (`decisions/001`), except `expert-realtime-rendering` (`decisions/003`).
- `/vibe:feature` and `/vibe:fix` consult up to 3 experts at plan time, in parallel, and one precise question per expert per sub-task during implementation.
- Runtime verification is delegated to the native `run` skill; 3 failed attempts write an entry to `.vibe/escalations.md` and escalate.
- Refactor and lint (and `vibe:release`'s pre-release checks) re-run the build command detected at baseline; a failing build blocks Commit exactly like a failing test.
- `/vibe:feature`, `/vibe:fix`, `/vibe:backlog`, and `/vibe:auto` never end a turn with uncommitted files (`wip:` when incomplete).
- Backlog references (`^\d+(-[\w-]+)?$`) are resolved by `workflow.md`; an item goes `in_progress` at start and to `done/` with a `chore:` commit at the end.
- `--auto` resolves every human gate by a fixed table and ends with an `AUTO-RESULT:` line — the only contract `/vibe:auto` relies on.
- `/vibe:auto` runs one item per sub-agent, strictly sequentially, and commits `.vibe/auto-state.md` at every item boundary so a run resumes; restarts come from `/loop`.
- `/vibe:auto` ranks eligible items by unblock count, then defects first, then lowest number; `/vibe:next-task` delegates its auto mode to `/vibe:auto --push`.
- `/vibe:review` records each run in `.vibe/last-review.md`; feature, fix, backlog, and auto surface a cadence hint after 5 unreviewed changes.
- `.vibe/glossary.md` is code-derived and self-cleaning through `_Sources:_` lines.
- `/vibe:workspace-init` and `/vibe:next-task` work above the single-repo level; a hub repo is recognized by `.git/` + `repos.md`; cross-repo blockers are prose, never `depends_on`.
- `/vibe:changelog` only fills `[Unreleased]`; `/vibe:release` cuts the version section; only `vibe:publish` pushes.
- `vibe:publish` polls the pushed commit's CI/deploy run (best-effort, GitHub only, bounded wait) and surfaces a failure as a blocker; `/vibe:auto`/`/vibe:next-task` lead their report with it instead of the usual `/loop` continuation suggestion.
- Generated `.vibe/` content and reports use short, plain sentences (`decisions/002`, superseded by `004` for the mechanism, not the style).
