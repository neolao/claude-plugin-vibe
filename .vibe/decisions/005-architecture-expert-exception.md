# Add `expert-architecture` despite `review-architecture` already existing
**Context:** `/vibe:feature`, `/vibe:fix` and the new `/vibe:consult` need ex-ante guidance on a design choice — a module boundary, the direction of a dependency, the pattern that carries an axis of variation, several plausible modelings of state that evolves over time. Decision `001` excludes this domain from the expert roster because it already has a review counterpart (`review-architecture`, plus the opt-in `review-alternative-design` which proposes a named alternative after the fact), specifically to avoid two near-duplicate expertise grids for one scope.
**Decision:** Add `expert-architecture` as the second documented exception to decision `001`, after `expert-realtime-rendering` (decision `003`). It prescribes before code exists — a named baseline, one or two named alternatives scored against it, a recommendation with its dependency — and returns a one-line `none` when there is no real design choice or the repo already prescribes the form. `review-architecture` and `review-alternative-design` keep critiquing after; the expert only moves part of that judgement before the code.
**Reason:** The same argument as decision `003`: a design choice is far cheaper to make before the code exists than to retrofit after a review. A reviewer that finds the wrong boundary once the code is written can only propose a migration; an expert consulted at plan time makes the migration unnecessary. Adding one expert on top of the existing reviewer, rather than an expert *and* a new reviewer, keeps the exception minimal — one new file, no self-contained mirror domain.
**Rejected alternatives:** (1) Widening `review-architecture` only — rejected: a reviewer runs on existing code and cannot shape a choice that has not been made yet, which is the actual gap. (2) Folding the design-choice grid into `skills/feature/workflow.md` as inline guidance — rejected: loses the independent perspective and the per-task selection that the `agents/expert-*` pattern gives, and cannot serve `/vibe:consult` outside feature/fix. (3) Lifting decision `001`'s rule altogether — rejected: two narrow, documented exceptions do not prove the rule wrong; each stays justified on its own cost argument.
