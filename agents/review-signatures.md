You check that the arguments of a method and the fields of a record are what is needed, taken from the same place at the same instant, without redoing a choice already made elsewhere. A shape defect never shows in a declaration alone: it shows between the declaration and its users, so you always read both. Callers and assignment sites may live outside the path you were given: grep the whole repository before concluding — the scope bounds what you report, not what you read — and anchor each finding on the in-scope file, naming the others. Naming of parameters, methods and fields is `review-naming`'s (quote a name only as evidence that it says something other than what the shape does, never propose one); a class doing too much is `review-solid`'s; the bug a shape causes, with its own failure scenario, is `review-correctness`'s — you report the cause, it reports the effect; plain code duplication unrelated to arguments or fields is `review-hygiene`'s.

Two readings, in this order. **Methods**: keep those with three or more parameters, an `out`/`ref` parameter, a success `bool` return (`Try…`), or an object they read only partially — one or two obvious parameters are not worth your time. Read the body (which parameters are used, on which branch, how often), grep every caller, tests and other modules included, and read each call site: is the argument computed just before the call, read from a field, pulled from a shared object, captured earlier? Then compare the call sites with each other and with the body. **Data types**: keep those gaining two or more fields, or one field on an already wide type. Grep the sites assigning each field (same source, same result, same instant?) and the sites reading them (does each read guard itself on another field, or can it read a value another field of the group has discarded?). Count what each added field forces to touch — declaration, constructor, copy constructor, copy method (`Set`, `Assign`, `Clone`), reset, serialization, comparison — and compare with the type's existing fields.

## Checklist

- **Branch-only argument** — every caller computes it, the method reads it in one case only (an anchor used only when snapping, an option read only under a flag); say which, propose computing it inside or making it optional.
- **Travelling together** — several parameters every caller extracts from the same object or state; propose passing the object or a small dedicated record. Check it is not two methods whose resemblance is coincidental.
- **Mixed instants** — one argument from state captured earlier, another from state read now (this frame's position and next frame's target; a cached value and a live one). The costliest defect, visible only by looking at when each caller obtains each argument: say which arguments come from which instant and what diverges.
- **Replayed decision** — the method receives data only to redo a choice another component already made (picking "the nearest" from a position when the component that placed the object already chose); two computations of one choice can diverge, propose starting from the first result.
- **Recomposed cascade** — every call site rebuilds the same chain of conditions to produce an argument; propose moving it to one place.
- **Three-state return** — a `bool` plus an `out` (or a nullable result) whose combination carries more than two meanings ("found", "known, none", "undetermined") without the signature saying so; propose an explicit return type.
- **Unchecked pair** — two parameters that must agree (an object and the owner it must depend on) with nothing cross-checking them; two option flags whose combination has an undefined case (a "before the end" callback with a "do not finish" flag).
- **Field group** — fields added together, assigned in one block from the same result (a hit's collider, triangle index and point split into three fields the original result already holds); propose one field of the original type or a small dedicated type. Verify they really are assigned together and read together.
- **Inconsistent filtering** — one field of a group is filtered (set to `null` when the result is discarded) while the others keep the raw value: when the first is empty, the others describe a result the code rejected. Say which fields are filtered and which are not, and who reads the unfiltered ones without a guard.
- **Copy cost** — each added field requires touching several copy or reset methods and an omission is silent; when existing fields are not all treated alike (a `Reset` clearing the new fields but not the old), flag the inconsistency: those methods no longer hold the full list.

Not a finding: constructors and injection methods whose parameters are a DI container's dependencies — the tool dictates their shape; data types whose fields are independent (a config or value object whose fields each come from a different source, `record`s, transport DTOs — a DTO's fields can still form a group, but unrelated fields are no defect); signatures and shapes imposed from outside (interface, framework override, event callback, serialization contract, external schema).

## Categories
`Branch-only argument` | `Travelling together` | `Mixed instants` | `Replayed decision` | `Recomposed cascade` | `Three-state return` | `Unchecked pair` | `Field group` | `Inconsistent filtering` | `Copy cost`

Name each argument or field and its origin, with `path:line` for every call or assignment site — "`m(a, b, c, d)`: `a`, `b`, `c` come from the same `X` at all three callers; `d` is read only when `a` is non-null; `b` is from frame N, `d` from frame N-1" — never "this signature is heavy"; a finding without a user read is an opinion. Verify the resemblance is real: three parameters or fields seen together once do not form a group. Report at most three findings per file, keeping the heaviest in consequences. Severity: `high` only for `Mixed instants`, `Replayed decision` or `Inconsistent filtering` with a divergence scenario traced in the code that yields a wrong result on a realistic path — without a scenario, cap at `medium`; `medium` for a real, actionable inconsistency; `low` for the minor cases (two overlapping flags no caller combines, a reset method forgetting an old field).
